`analysis/horizon.py` reconstructs the three retained collections a stream reveals. Two more are
retained and invisible there: the previous tick's decision snapshots, which no event reports, and the
collected-event vector the text host leaves absent. Peak working set is the only instrument that
reaches them, and the criterion is a ratio rather than a limit -- twenty times the ticks against a
5% memory band -- because the absolute figure is this machine's and the ratio is the world's.

Four invocations are recorded, each with its exit code. The second is the instrument's own control:
a flat column measures nothing unless the same reading is shown to move when memory really is held.
The third and fourth are the ladder taken again, unchanged, because a spread of a few KiB is only
interpretable beside the spread the same command produces on its own -- and one of the two reads a
larger spread from re-running one cell than from twenty-fold-ing the tick count.

The engine's peak sits at about 4.3 MB and does not move with the tick count. Across the three
ladders above the 10,000-tick cell reads 4344, 4332 and 4344 KiB and the 20,000-tick cell reads
4336, 4332 and 4336: twice the ticks, and the longer run never reads higher. The three ladder
spreads are 16, 8 and 20 KiB while the same cell re-run three times moves 8, 12 and 8 KiB, and in
the second ladder the re-run band is *larger* than the whole spread the tick count produces. A
figure that is not reproducible from one invocation to the next is the measurement's and not the
world's, and that is what these three say.

The control holds 48 MiB more than its first run and the same reading moves by 49,188 KiB, so the
column is flat because nothing accumulates rather than because nothing is being read.

Provenance of the identifier
--------------------------------------------------------------------------------

The four invocations above were taken while the work order was numbered WO-MOK-012, which is the path
their command lines name. Both the work order and its verification artifact were renumbered on
2026-08-21 -- to WO-MOK-016 and VER-MOK-016 -- because WO-MOK-012 had by then been taken by a different
work order, already merged to master.

Every other reader in this packet was re-run at the new path, and each reproduced its retained output
byte for byte, which is what shows the renumbering changed no figure. `peak.py` was not, and the reason
is the finding this file exists to record: its output is not reproducible from one invocation to the
next. Re-running it would have replaced four honest measurements with four different ones and left the
tick-count spread resting on a fresh set of figures rather than on the three ladders that disagree.
What is retained is therefore what was measured, at the path it was measured under; the same command is
runnable today at `evidence/WO-MOK-016/analysis/peak.py`, and it will report different absolute
kilobytes, which is section 3's point.
