WO-MOK-018 — THE WITHDRAWN ONE-LINE FORM, captured as a counterfactual

This is not the implemented presentation. It is the four values on one line — the form the
implementation carried before rule 10.6's two-line pairing — rendered by the same oracle into
the same panes, so that the pairing's justification is a measurement rather than an argument.
The pairing is an OUTSTANDING provision awaiting the technical owner's ratification, and this
file is the material for that decision. `inspector.txt` beside it is the implemented form.

It was produced by temporarily replacing the two-line block in `mokiterions-tui/src/render.rs`
with the one-line form, running the oracle, and reverting. The revert was verified by SHA-256
against the file's digest before the edit, so the tree the gates were run on is byte-identical
to the tree that produced this capture's counterpart.

The banner below is the oracle's own and describes the amended rule, not this rendering.

WO-MOK-018 — the inspector pane for a dead subject

Captured by a temporary oracle, which asserts nothing. Every row below is read out of a
rendered buffer cell by cell, including the pane's own border, so a value clipped off the
pane is visible here as an absent character rather than as a shorter string.

`SPEC-MOK-003` rule 10 item 6 as amended 2026-08-21 fixes four presented values for a
dead subject and pairs them across two lines. Rule 10 item 7 makes an unreported value
absent rather than zero-filled. The two cases below are those two provisions.
