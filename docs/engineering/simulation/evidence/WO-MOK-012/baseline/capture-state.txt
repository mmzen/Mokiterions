VER-MOK-012 oracle 1 requires the capture "taken before any code change from a tracked-clean worktree,
with the commit recorded", and adds that "a discrepancy is never resolved by recapturing it". A
statement that a tree was clean is an assurance. What follows is that claim measured, the same way
WO-MOK-011 measured it, and it is stronger than the statement: the capture is reproduced cell for cell
from a tree that cannot contain a working-tree modification at all.


1. The state of the worktree at capture
---------------------------------------

    $ git rev-parse HEAD
    39662d13abd08e3410648d1c59ad38384f8ad2d2
    $ git diff --stat HEAD
    (no output)
    $ git status --short
    ?? docs/engineering/simulation/evidence/WO-MOK-012/

Tracked-clean, with one untracked path: this evidence directory itself, holding capture.sh and the
scripts under baseline/. That is the only untracked content in the tree, it is committed together with
these results, and no part of it is compiled or read by the engine. Section 2 measures rather than
argues the point.

The commit is the approval act, 39662d1, and no source file has been touched since: the capture is
taken before any code change, which is what makes it a baseline at all.


2. The capture is the baseline commit's own output
--------------------------------------------------

    $ rm -rf <scratch>/recap-tree <scratch>/recap && mkdir -p <scratch>/recap-tree
    $ git archive $(cat baseline/COMMIT.txt) | tar -x -C <scratch>/recap-tree
    $ cd <scratch>/recap-tree && cargo build --release --offline -p Mokiterions
       Compiling Mokiterions v0.1.0 (<scratch>/recap-tree/mokiterions-core)
        Finished `release` profile [optimized] target(s) in 3.54s
    $ bash <repo>/docs/engineering/simulation/evidence/WO-MOK-012/capture.sh <scratch>/recap
    captured 90 streams into <scratch>/recap

`git archive` writes the commit's trees and nothing else: no untracked file, no working-tree
modification, no index state. The archived tree does not contain evidence/WO-MOK-012/ at all -- that
directory is untracked at this commit -- so capture.sh is invoked from the repository while the working
directory is the archived tree. capture.sh addresses the binary as ./target/release/Mokiterions, so it
runs the archived tree's engine, and using one script on both sides is deliberate: it makes the
comparison a statement about the tree and not about the harness.

Every cell was then digested with baseline/manifest.py and compared with baseline/pre-manifest.txt on
four columns at once -- raw SHA-256, byte count, line count and exit code:

    cells in pre-manifest.txt:                                  90
    reproduced exactly (raw digest, bytes, lines, exit):         90
    mismatched:                                                  0

The comparison is a plain diff of the two manifests with the label line excluded, because the two runs
label themselves differently and agree on everything else.

The cell retained whole in this packet, and read directly rather than by digest, is among them, and its
row in pre-manifest.txt is reproducible from the committed file itself:

    seed42-baseline-d0.75-traceon    c777bc0ae1a322a447639b81dd502d3b2b84e7d4d4e7d097585fe3d987ec42c8

    $ sha256sum < baseline/full/seed42-baseline-d0.75-traceon.txt
    c777bc0ae1a322a447639b81dd502d3b2b84e7d4d4e7d097585fe3d987ec42c8

That equality survives a Windows clone because .gitattributes already carries
`docs/engineering/simulation/evidence/** -text`, added while committing WO-MOK-010 for this exact
failure: with core.autocrlf = true and no such rule, checkout rewrites every retained stream to CRLF and
every recorded digest then fails against a file whose content is correct. The manifest is of the capture
as the engine wrote it, LF, and the working tree holds those bytes unchanged.

Any tracked modification present when the capture was taken would have to have left all 90 streams
byte-identical to the commit's own output to escape this check.


3. What is not measured here
----------------------------

There is no post-change capture yet. This packet is the pre-change side alone, taken at the moment
implementation began, and the comparison oracle 1 exists for happens later, at the candidate. The
figures here are what that comparison will be taken against, which is why they are recorded before any
code is written rather than reconstructed afterwards.

Both scratch captures -- the original and the reproduction -- were written outside the repository, at
110 MB each, and deleted after measurement. That is why this file records the outcome and not the
streams. retain.py states what is kept instead, cell by cell, and why each piece is worth its bytes.

cross-check.txt records a second and independent agreement: all 90 cells also match WO-MOK-011's
post-change capture, as an unchanged source tree predicts.

RESULT: PASS -- the pre-change capture is reproducible from the commit it claims, 90 of 90 cells on
four columns, from a tree that cannot have been dirty.
