Result
------

    212 before, 246 after, 34 additions, 0 removals, 0 renames.
    246 passed, 0 failed, 0 ignored, 0 filtered out. No `#[ignore]` anywhere in either package.

The reconciliation is by qualified name, not by count: a case that moved between tiers or between
targets would appear here as one addition and one removal even with the total unchanged. None does,
and 0 removals is what makes 0 renames a fact rather than an assumption — a rename cannot hide in an
addition-only diff.

A limitation of the primary tool, disclosed rather than worked around. `census.py` qualifies every
test by the first word after `Running`, which for a unit-test target is the literal word `unittests`.
The workspace has four unit-test targets — the engine's library and binary, the observer's library
and binary — so all four collapse into one qualifier there. That is the collision the tool's own
docstring warns about and `WO-MOK-011`'s retained census has it too. `analysis/census-by-target.py`
runs the same two logs again, qualifying by the test binary Cargo names on the same line, which
distinguishes all four. It reports the same 34 additions and the same 0 removals, so the collapse
changed nothing here; had a test moved between the four collapsed targets under one name, the finer
pass would have shown it and the primary one could not. `analysis/census-by-target.txt` is that pass.


The thirty-four additions
-------------------------

Engine, internal tier — `mokiterions-core/src/simulation.rs`, fourteen:

    unittests :: simulation::tests::the_header_record_states_the_resolved_configuration_and_never_a_path
        SPEC-MOK-006 rule 5's nine fields, each against the authority that declares its value, and
        the absence of the destination among them. Rule 5.4's counterexample key `events_path` is
        checked absent by name.
    unittests :: simulation::tests::every_event_kind_has_its_exact_record_shape
        All twelve kinds of rule 3.2's enumeration, each compared to the shape rule 6.5 fixes for
        it, including two shapes no shipped decision source produces.
    unittests :: simulation::tests::every_proposal_shape_is_the_action_word_and_the_one_value_it_carries
        Rule 6.5's third composite shape, by exhaustive match over the proposal enumeration, so a
        member added later cannot be omitted from the check.
    unittests :: simulation::tests::a_metrics_record_over_an_empty_living_population_reports_null_extrema
        Rules 7.5 and 4.4 at the one boundary where a fact does not exist: the whole record is
        asserted, not only the two null fields.
    unittests :: simulation::tests::every_cumulative_counter_equals_its_event_count_in_the_text_stream
        Rule 8.6, with the counts taken from the run's own *text* stream rather than from the
        records, so the two witnesses are independent.
    unittests :: simulation::tests::a_saturated_counter_neither_wraps_nor_panics
        The counters are `saturating_add`, and this pins the behaviour at the ceiling rather than
        leaving it to the type.
    unittests :: simulation::tests::no_rule_reads_a_cumulative_counter
        Behavioural, not structural: the counters are pre-loaded with arbitrary values and the run
        must not diverge. A rule that read one would.
    unittests :: simulation::tests::every_closed_domain_that_reaches_a_record_is_on_the_alphabet
        Oracle 5. Thirteen domains enumerated member by member, each member's characters checked
        against the union rule 3.3 fixes, and each domain's *size* checked against the number
        SPEC-MOK-006 states — which is what makes the totality argument hold and what
        `negative-controls.txt` scenario 6 breaks.
    unittests :: simulation::tests::a_recorded_run_writes_the_same_text_bytes_as_an_unrecorded_one
        Rule 11.1 from inside, at every policy with tracing on.
    unittests :: simulation::tests::a_record_sink_moves_no_entropy_draw_at_any_tick_boundary
        Oracle 4, and REQ-MOK-045's substance. Retained in `entropy.txt` Part 5 and broken
        deliberately in `negative-controls.txt` scenario 4.
    unittests :: simulation::tests::the_entropy_state_after_initialization_is_the_seed_and_the_density_alone
        Rule 11.1's additivity: one value across all twelve combinations of policy, tracing and
        sink, per declared seed and swept density. `entropy.txt` Part 1.
    unittests :: simulation::tests::the_entropy_state_at_the_thousandth_tick_is_unmoved_by_a_sink
        The same comparison at the end of a full run rather than at a boundary. `entropy.txt` Part 2.
    unittests :: simulation::tests::a_record_sink_that_fails_at_once_ends_the_run_before_any_text_is_written
        Rules 13.3, 13.5 and 13.2 together: a sink that fails on its first write stops the run
        before the text stream has a line, and the diagnostic says which stream failed.
    unittests :: simulation::tests::a_record_sink_that_fails_mid_run_leaves_no_run_record
        Rule 8.9. A truncated stream must not carry a run record, because a run record is a claim
        that the run finished.

        All fourteen are inside the crate because each one names something the interface does not

        `Sinks` value built over a failing writer. `static-checks.txt` item 11 enumerates the nine

        item 9 does the same for the entropy accessor alone, which is the one item this work order
        added for a test's sake. That is SPEC-MOK-002 rule 7's test applied rather than a judgement

A note on the one pre-existing test that changed
------------------------------------------------

`mokiterions-core/tests/cli.rs`'s USAGE-versus-parser test gained the sink option, which is the
extension WO-MOK-012's *What may change* admits by name. No other pre-existing test's body or
assertions changed, which is WO-MOK-012 stop-and-escalate condition 4: "Any existing test's
assertions would have to change, beyond the mechanical `execute` call sites and the extended
`USAGE`-versus-parser test." The `execute` call sites that condition anticipates in
`mokiterions-tui` do not exist — the observer does not call it — and `completion-summary.md` records
that as a defect in the work order rather than a change made silently.
