Making the registry unreachable rather than asserting it
-------------------------------------------------------

--offline tells cargo not to use the network. That is cargo's promise, not a measurement of
it, so every command below also runs with an HTTP proxy pointed at a closed port:

    CARGO_HTTP_PROXY=http://127.0.0.1:1

Control first -- a command that does need the registry, under that proxy, so that a
succeeding build below cannot be a proxy that was never consulted:

    $ CARGO_HTTP_PROXY=http://127.0.0.1:1 cargo search ratatui --limit 1
    error: failed to retrieve search results from the registry at https://crates.io
    
    Caused by:
      [7] Could not connect to server (Failed to connect to crates.io port 443 via 127.0.0.1 after 2003 ms: Could not connect to server)
    exit 101

What this establishes, and what it does not
------------------------------------------

It establishes that the engine package resolves, compiles and tests from the committed lockfile
with the registry provably out of reach, which is what SPEC-MOK-005 rule 8.4c now requires as a
check. Before ADR-MOK-006 this was a side effect of the engine's dependency table being empty:
nothing to fetch, so nothing to be offline about. The table is no longer empty by rule -- it is
empty by measurement -- so the property is asserted here instead of inferred.

It does not establish anything about the observer. `cargo build -p mokiterions-tui --offline`
needs the `ratatui` graph in the local cache, and a build on a machine with an empty cache would
fetch it. The offline claim in this repository is about the engine, and rule 8.4c says so.

It does not establish that the engine has no dependencies -- `cargo tree` does that, in
WO-MOK-013-graphs.txt, one node per target. A package can depend on crates already in the cache
and still build offline.
