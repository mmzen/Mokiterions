# Verbatim comparison: is every relocated test's body character for character what it was?
#
# `VER-MOK-006` conformance check: "A relocated test's body is unchanged. Only its imports change,
# and only from a path inside the crate to the same path through the library target's name."
#
# This is the check that a census cannot make. 169 names surviving on both sides says nothing about
# whether the assertions behind them survived; a relocated test could have been quietly weakened to
# make it compile outside the crate and the count would not move. So each test's text is extracted
# from the predecessor commit and from the candidate and compared directly.
#
# Method. Predecessor: 191db01. A test's text runs from its first documentation or attribute line
# through its closing brace, found by a brace scanner rather than by indentation. A relocated test's
# predecessor text sat one level in, inside a `#[cfg(test)] mod tests { ... }` block, so it is
# dedented by exactly four spaces before the comparison; `verification.rs` is a test module in its
# entirety on both sides, so its tests sit at indent zero and are compared with no dedent. A
# retained test is compared with no normalisation at all. Nothing else is normalised — not
# whitespace, not comments, not blank lines. Any difference is printed in full as a unified diff,
# which is what makes the check able to fail.

  ## render::press — the one helper whose text is not identical

     --- 191db01 (mokiterions-tui/src/render.rs, inside `mod tests`, dedented four spaces) ---
     fn press(code: ratatui::crossterm::event::KeyCode) -> ratatui::crossterm::event::KeyEvent {
         ratatui::crossterm::event::KeyEvent::new(
             code,
             ratatui::crossterm::event::KeyModifiers::NONE,
         )
     }

     --- candidate (mokiterions-tui/tests/render.rs) ---
     fn press(code: ratatui::crossterm::event::KeyCode) -> ratatui::crossterm::event::KeyEvent {
         ratatui::crossterm::event::KeyEvent::new(code, ratatui::crossterm::event::KeyModifiers::NONE)
     }

     Same call, same arguments, same order, joined onto one line. The cause is measurable rather
     than a matter of judgement: the joined call line is 97 columns at file scope, and was 101 at
     the predecessor's deeper indent, one column past `rustfmt`'s default `max_width` of 100. There
     is no `rustfmt.toml` in this repository, so the default applies. Moving the helper out one
     level brought the line under the limit and `cargo fmt` closed the wrap. `cargo fmt --all
     --check` passes on the candidate, which is the same formatter reaching the same verdict.

     It is recorded as a difference rather than waved through as cosmetic because the comparison's
     value comes from printing everything it finds. Nothing in it changes which `KeyEvent` the
     helper builds: `KeyEvent::new(code, KeyModifiers::NONE)` on both sides. The two other `press`
     definitions, in `state.rs` and `verification.rs`, are the eight-line struct-literal form and
     are byte-identical after dedent — so the two forms that existed before still both exist, with
     the same difference between them they always had.

# What this establishes, and what it does not
#
# It establishes that the assertions did not change. Combined with `test-census.txt`, which shows
# no name added, removed or renamed, and with `test-run.txt`, which shows 169 passing and 0 ignored,
# the observer's test suite asserts after this change exactly what it asserted before it.
#
# It does not establish that the tests still exercise the same code — a test can be unchanged and
# still be linked against something different. That is what `non-test-content.txt` is for: all seven
# `pub mod` files are byte-identical outside their test blocks, so the code under test is the same
# code as well.
