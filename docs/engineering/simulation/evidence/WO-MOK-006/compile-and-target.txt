#
# `SPEC-MOK-004`'s Performance section predicts a cost and attaches no threshold to it. There is no
# conformance check here to pass or fail. This file exists because the prediction was made and should
# be measured rather than assumed, and because the number it predicted turns out to be off by one.
#
# Method. Each tree gets `cargo clean` and then a timed cold `cargo build --workspace`, followed by
# `cargo test --workspace --no-run`, which reuses the build above and so measures only the extra work
# of linking the test binaries. The predecessor was measured in a scratch worktree at 191db01 with
# its own `target/`. Wall-clock on a shared laptop: treat these as the right order of magnitude, not
# as repeatable benchmarks.

## Read together

                                predecessor   candidate   change
    cold `cargo build`             14295 ms    10714 ms   -25%
    `cargo test --no-run`           2974 ms     3735 ms   +26%  (+761 ms)
    warm `cargo build`                    —      270 ms
    warm `cargo test --no-run`            —      263 ms
    test binaries                         8          17   +9
    `target/` after a full test build    349M        499M   +150M

  The cold build got *faster*, which is measurement noise rather than an effect of the change: the
  same 59 crates are compiled either way — `dependencies.txt` shows the graph is identical and
  `Cargo.lock` is byte-identical — and a 25% swing between two cold builds on a laptop is ordinary.
  Nothing in this change could make compilation faster.

  The honest cost is the +761 ms on `cargo test --no-run` and the +150M in `target/`. Nine more test
  binaries is where both come from: eight new integration binaries under `mokiterions-tui/tests/`
  plus the observer's new library test binary. Each links the library and ratatui separately, and
  each is a separate executable on disk. That is the price of the public tier, it is paid once per
  clean build, and the warm figures — 270 ms and 263 ms — are what anyone iterating actually pays.

  A three-quarter-second addition to a cold test link, against 77 tests that now assert the
  observer's contract from outside the crate as `REQ-MOK-028` requires. `INT-MOK-005` accepted that
  trade when it was proposed; this is the invoice.

## The prediction, and where it is off
#
  `SPEC-MOK-004`'s Performance section says "the observer contributes eleven test binaries where it
  contributed one". The measured figure is ten: the library, the binary, and eight integration
  binaries — visible in the candidate listing above, where the observer accounts for `mokiterions_tui`
  twice (`src\lib.rs` and `src\main.rs`) and then eight `tests\*.rs`. Eleven is the number of *result
  lines* `cargo test -p mokiterions-tui` prints, which includes the `Doc-tests mokiterions_tui`
  target — a target, not a test binary, and one that runs 0 tests.

  Nothing follows from the discrepancy: the section states an expected cost, sets no threshold and
  imposes no obligation, so there is no check to fail. It is recorded because a specification's
  number should be right, and carried to the completion report for the owner to dispose of.

  The workspace total the same section implies is 8 + 9 = 17, and 17 is what was measured.
