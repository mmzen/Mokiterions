## The other three forms

  $ cargo test -p Mokiterions
      60 passed in total, against the expected 60
      8 result lines, all ok, 0 failed, 0 ignored
      exit=0

  $ cargo test -p mokiterions-tui
      109 passed in total, against the expected 109
      11 result lines, all ok, 0 failed, 0 ignored
      exit=0

  $ cargo test   (the bare form, at the workspace root)
      169 passed in total, against the expected 169
      19 result lines, all ok, 0 failed, 0 ignored
      exit=0

  An adverse observation, recorded here because this is where it is measurable. `SPEC-MOK-004`'s
  Performance section predicts that "the observer contributes eleven test binaries where it
  contributed one". The measured figure is ten: the library, the binary, and eight integration
  binaries. Eleven is the count of *result lines* for the package, which includes the `Doc-tests
  mokiterions_tui` target — a target, not a test binary, and one that runs 0 tests. The prediction
  is off by one on the reading its own words carry. Nothing follows from it: the section states an
  expected compile-time cost, attaches no threshold and no obligation, and `compile-and-target.txt`
  measures the actual cost. It is carried to the completion report for the owner to dispose of.

  The bare form matters for the same reason the bare Clippy form does: at the root of a virtual
  manifest it resolves to the default members, so it runs both packages. Before this change it ran
  the root package only, and CI's bare invocation silently never ran the observer's tests at all.
  That the bare form now reports 169 rather than 60 is the change CI needed.

## What a passing run does and does not establish
#
  It establishes that the relocated tests compile as external crates and still hold. A test that
  reached a private item or a `#[cfg(test)]` hook could not have compiled from `tests/`, so 77
  passing integration tests are themselves the proof that each is writable through the public
  interface — the compiler decided the tier, not a judgement.

  It does not establish that they assert what they used to. `verbatim-comparison.txt` is that
  check: 76 of the 77 bodies are byte-identical to the predecessor's and the 77th differs only in
  one path, twice. And `test-census.txt` establishes that the 169 are the same 169, name by name,
  rather than 169 of anything.
