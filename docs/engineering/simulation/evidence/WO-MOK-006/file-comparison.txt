# File comparison: the engine moved, and nothing in it changed
#
# `VER-MOK-006` conformance check: "Every one of the engine's nine source and test files is
# byte-identical to its predecessor at 191db01. The only changes anywhere are path references."
#
# Method. A working-tree file cannot be compared with a committed blob by reading bytes off disk:
# this repository normalises line endings, so every retained file is CRLF on disk and LF in the
# object store, and a naive `diff` reports nine spurious differences. The comparison is therefore
# made in the object store. `git hash-object --path=<new path> <file>` applies the same clean
# filter Git would apply on commit and prints the blob id the file would have; `git rev-parse
# 191db01:<old path>` prints the blob id it had. Equal ids mean equal content, and the method is
# immune to line-ending translation because both sides pass through the same filter.

# Every path reference that changed, and why each one had to
#
# The conformance check permits path references to change and nothing else. There are seven, and
# this is all of them.
#
#  1. `Cargo.toml` at the root — REPLACED, and the old one MOVED
#
#     The old root manifest was two things at once: the workspace manifest and the engine package's
#     manifest. It moved to `mokiterions-core/Cargo.toml`, where its `[package]`, `[lib]`, `[[bin]]`
#     and `[dependencies]` tables stand unchanged, and its `[workspace]` table was removed from it.
#     A new virtual manifest took its place at the root, holding `[workspace]` and nothing else:
#
#         members = ["mokiterions-core", "mokiterions-tui"]
#         resolver = "3"
#
#     `members` names both packages where it named one, because the engine is no longer the root
#     package that a workspace implicitly includes. `resolver = "3"` is declared because a virtual
#     manifest does not inherit a member's edition default and Cargo warns without it.
#
#  2. `mokiterions-core/Cargo.toml` — the `[workspace]` table removed, and a new comment
#
#     Every path inside it is unchanged: `path = "src/lib.rs"`, `path = "src/main.rs"`. A package
#     manifest's paths were always relative to the manifest, so moving the manifest and the two
#     directories together left them correct. `manifests.txt` shows the whole file.
#
#  3. `mokiterions-tui/Cargo.toml` — `path = ".."` became `path = "../mokiterions-core"`
#
#     The dependency is the same package, `Mokiterions`, reached at its new location. The `[lib]`
#     table added beside it is not a path reference; it is the new library target, which is the
#     substance of the change and not a consequence of the move.
#
#  4. `mokiterions-tui/src/main.rs` — seven `mod` declarations became three `use` statements
#
#     `mod authority; mod export; ... mod state;` became
#     `use mokiterions_tui::{layout, options, render};` and two more `use` lines. The binary now
#     reaches the presentation layer the way anything outside the crate does. Declaring the same
#     modules in both targets would compile them twice and give the package two copies of every
#     type, so this substitution is forced rather than stylistic. `verbatim-comparison.txt` records
#     that all eight of the file's tests are byte-identical across it.
#
#  5. `mokiterions-tui/src/lib.rs` — NEW
#
#     The seven `pub mod` declarations, module documentation citing `ARCH-MOK-002` component 5,
#     `REQ-MOK-028` and `SPEC-MOK-004` rules 4 to 7, and `#[cfg(test)] mod verification;`.
#
#  6. `crate::state::EVENT_CAPACITY` became `mokiterions_tui::state::EVENT_CAPACITY`
#
#     Two occurrences, both inside one relocated test. `verbatim-comparison.txt` shows the diff.
#     This is the only path reference that changed inside any test body.
#
#  7. `.idea/Mokiterions.iml` — the module's source roots
#
#     A tracked JetBrains module file that lists the project's source and test roots. It named
#     `src` and `tests` at the repository root, which no longer exist. It now names
#     `mokiterions-core/src`, `mokiterions-core/tests`, `mokiterions-tui/src` and
#     `mokiterions-tui/tests`. The IDE had already added the four new entries on its own; the two
#     stale ones were removed by hand, because a tracked file that describes the layout should not
#     go on describing the old one. No other `.idea` file names a path that moved: `.gitignore`,
#     `modules.xml` and `vcs.xml` are unchanged.
#
# Nothing else in the observer's `src/` names a path. The seven `pub mod` files use `crate::` to
# reach each other and they are still one crate, so `non-test-content.txt` finds all seven
# byte-identical outside their test blocks — including every `use` line in them.
#
# The eight new files under `mokiterions-tui/tests/` are new files, not changed ones. Each carries a
# `use mokiterions_tui::...` header, which is the path reference by which a separate crate reaches
# the library; `test-placement.md` bounds what those headers may name and the compiler enforces it.
