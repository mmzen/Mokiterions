VER-MOK-007 oracle 3 - equivalence with the reference source at tolerance 0 - negative control
=============================================================================================

Acceptance scenario 3 requires that the equivalence check be shown able to fail. Rule 19
is written so that at tolerance `0` its tolerant test reduces to rule 5's exact-fit test,
and two sources that agree are indistinguishable from two sources that are not being
compared. These two controls separate those cases: each makes the trait-aware source differ
from the reference source at tolerance `0` in one of the two ways the oracle asserts about --
the proposal it returns, and the position it leaves the stream in.

Each perturbation below was applied to the committed source, the engine's own suite
was run, and the perturbation was reverted and the file checked byte for byte against
its digest. This artifact is generated by negative-control/controls.py from those
runs.

Control A - the tolerant bound, off by one
------------------------------------------

  mokiterions-core/src/simulation.rs, Observation::fits_within_tolerance:

  -        resulting - maximum <= u16::from(self.waste_tolerance) * restored / 100
  +        resulting - maximum <= u16::from(self.waste_tolerance) * restored / 100 + 1

Rule 19 states the admitted waste as `T * R / 100`. With `+ 1` the test admits one
unit more than the rule allows, and at tolerance `0` it admits one unit of waste where
rule 5 admits none -- so the two sources no longer propose the same action.
