`SPEC-MOK-004` rule 6 records the observer's interface as **94 items, 118 `pub` lines and 24 public
fields**, and `WO-MOK-011` claims the naming work leaves all three untouched. The packet measured
that against the branch base. This file measures it against `master` at 2157f77 and against the
merge, because the merge is the first tree in which both this work order's names and `master`'s
survival bands exist, and rule 6 is a figure about that tree.

The enumeration is mechanical and rule 6's figure is the enumeration minus `lib.rs`'s seven
`pub mod` declarations, which rule 6 excludes as module plumbing rather than interface:

  observer, master        101 items  125 pub lines  24 public fields   ->  94 / 118 / 24

That is a parameter name in a signature whose arity, types and return are unchanged. It is not an
item, not a `pub` line added or removed and not a public field, so **every figure rule 6 records is
unchanged by measurement rather than by assumption**, and `SPEC-MOK-002`'s engine interface is
byte-identical.

`Observer::name_of`, which the observer reads the name through, is `pub(crate)` and therefore in
neither figure. That is the whole reason rule 6 does not move under this work order.
