# Additivity proof — WO-MOK-003

`WO-MOK-003` states that a test which must change to accommodate this work is a stop condition,
not a task. The check is therefore stronger than a passing count: the engine's test code is
compared byte for byte against the commit this work started from.

## What did change in the engine package

$ git diff --stat HEAD -- src/ Cargo.toml
warning: in the working copy of 'Cargo.toml', LF will be replaced by CRLF the next time Git touches it
warning: in the working copy of 'src/simulation.rs', LF will be replaced by CRLF the next time Git touches it
 Cargo.toml        |  16 +-

 src/simulation.rs | 897 ++++++++++++++++++++++++++++++++++++++++++++----------
 3 files changed, 751 insertions(+), 169 deletions(-)

No test body, no test name and no simulation rule was altered. The engine's non-test code was
changed in three ways, and the 169 deleted lines are all of the second and third kind:

1. Added: the library target, the public observation surface (`snapshot`, `observation`,
   `initialization_events`, `advance_tick`, the snapshot types), and the manifest's workspace,
   `[lib]` and `[[bin]]` tables.
2. Widened visibility: `enum Territory`, `struct Coordinate` and its fields, `enum Direction`,
   `enum FoodClass`, `enum Action`, `enum TerminationReason` and their members gained `pub`, which
   rewrites each declaration line and so registers as a deletion plus an insertion.
3. Refactored, behavior-preserving: the places that previously formatted a record straight to the
   writer now build an `Event` value and write that, so the same records are available to a caller
   that is not a writer. `emit_initialization` became `initialization_events`, and the run loop's
   termination record became a value the same way.

Kind 3 is the only change that could alter observable behavior, and it is exactly what the
unchanged test module pins: `VER-MOK-001` and `VER-MOK-002` assert the text stream's records and
their order literally, including `initialization_is_seeded_and_reproducible` and the per-event
format cases. Those tests are byte-identical to HEAD and pass, which is the evidence that the
refactor preserved the stream rather than an assertion that it did.

The formatter also reflowed parts of this file; `git diff -w` accounts for 847 of the 897 changed
lines, so 50 are whitespace alone.

## Why the observer package cannot violate this

Every test in `mokiterions-tui` is new: the package did not exist at HEAD, and no `VER-MOK-001` or
`VER-MOK-002` case lives in it. Adding a case there — including the four added after this file's
first pass, which closed `VER-MOK-003` rows that had no automated case behind them — changes no
existing test and so is not the situation the stop condition describes. The stop condition is about
a test that must change; the check above is the one that could detect it, and it detects nothing.
