  A THIRD AMENDMENT, and it is not a bookkeeping one. Every reading in this file above was
  taken on Windows and none of them says so. Two of them were true of Windows only.

  Commit dbc9e6d fixes a defect that CI's Linux lane found and that no local gate could:
  fs::File::open on a directory succeeds on Linux and refuses only at the first read. Both
  hosts opened the transcript and handed the reader straight to ReplayPort, so on Linux a
  directory named as a transcript began the run. The engine binary printed the whole of tick 0
  to standard output before failing; the observer entered the terminal and stayed there. On
  Windows the open itself fails, so neither happened and every gate was green.

  What that means for this file: the four Rust gates below were a platform-limited reading, and
  the one test that should have caught the defect was written in a way that could not. Its
  directory case asserted assert_ne!(code, Some(0)) rather than the exit code, and it asserted
  an empty standard output at a point where the partial run had already been written -- so the
  assertion that failed on Linux was the one about output, and the exit-code assertion that
  would have named the defect was never strict enough to fire. That test now asserts the
  missing file's case exactly: exit 1, empty standard output, the host's message naming the
  path, and no usage text.
