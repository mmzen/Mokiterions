1. The correction consumes no entropy
-------------------------------------
If `fits_within` drew from the shared stream, every divergence in `post/divergence.txt` would
be confounded -- "the condition changed an answer" and "the condition moved the stream" would
be indistinguishable, and route R2 there would be unfalsifiable rather than merely permissive.
So the corrected function and every function that reaches it are read for stream contact.

same question is asked of everything those seven can reach, transitively:

    functions reachable from the seven, including themselves    9
    of those, functions that reach the shared stream            0
    **Nothing the corrected condition can reach touches the shared stream.** So a
    divergence recorded in `post/divergence.txt` cannot be a stream displacement created
    inside the condition; it is a changed answer, or a consequence of one.

    The scope of that negative claim, stated rather than left to be assumed: the scan covers
    the engine module ahead of `#[cfg(test)]` at line 3056, matching `next_u64`,
    `choose_index`, `entropy`, `SplitMix64` and `DecisionEntropy` as whole words, and the
    call graph is followed by bare callee name -- which over-approximates, so the closure
    scans more than the path can truly reach rather than less. What it cannot see is a draw
    reached through a trait object or a closure stored elsewhere, which is why the suite's
    `no_resolution_and_no_targeted_move_touches_the_shared_stream` remains the primary
    guarantee and this is a check on the correction specifically.

2. The stream's state at the end of initialization, at both commits
-------------------------------------------------------------------
`SplitMix64::new(seed)` sets `state = seed`, and `next_u64` advances the state by exactly one
fixed increment before mixing. So the absolute state after `k` values is
`seed + k*GAMMA (mod 2^64)`, and a draw count converts to a state without inverting the mixing
function. `choose_index` costs exactly one value for both bounds in play -- 128 for `x` and 64
for the territory-local `y` -- because each divides 2^64, so the rejection threshold
`bound.wrapping_neg() % bound` is zero and no value is ever rejected for modulo bias. That is
asserted rather than assumed, because it is what makes "two values per coordinate attempt"
exact.

4. Every resolution kind, counted either side of the correction
---------------------------------------------------------------
`attack_resolved`, `threat_resolved` and `surrender_resolved` are the resolution kinds, and
rule 26 emits them whether or not actions are traced. Two thirds of the matrix cannot contain
one at all, and that is worth establishing before the table rather than leaving a reader to
read three pages of zeros as a bug: a resolution is the settlement of a contested action, and
only the social source ever proposes one. So the resolution half of this retention item is
informative under `social` and vacuous everywhere else. The zeros below are proved rather than
merely observed:

5. The residual gap: the total draw count per run
-------------------------------------------------
The second half of the retention item asks for "the total draw count per run per source at
matched seeds". It is not derivable at this candidate, and this section is the record of that
rather than a proxy dressed as an answer.

    what would be needed                      why it is unavailable here
    a counter on the released surface         WO-MOK-017 Out of scope: "any new attribute,
                                             event, interface item or instrumentation".
                                             `--help` lists no such option and the rule 18
                                             summary carries no such field.
    a full replay outside the crate          a regeneration spends an unknown number of
                                             draws, because occupancy rejections are
                                             invisible -- only the accepted position is
                                             printed. Recovering them means replaying every
                                             draw-consuming path, which is a second
                                             implementation of the engine.
    a golden-value test in the suite         no requirement states a draw total, so such a
                                             test would pin an arbitrary measured number and
                                             fail on any later legitimate behavior change.
                                             SPEC-MOK-002 rule 12 is the neighboring
                                             principle: a test's assertion is its meaning.

What stands in its place, all of it measured above rather than argued:
  * the initialization draw total and absolute stream state, at all fifteen declared pairs and
    identical at both commits (section 2), validated against the suite's own recorded counts;
  * the initialization prefix byte-identical in all 120 cells, so every run enters tick 1 at
    the same stream state at both commits (section 3);
  * every resolution kind counted per cell at both commits, with `baseline` unmoved and
    tracing shown to move no draw (section 4);
  * the correction itself shown to consume no entropy (section 1), which is the premise that
    makes `post/divergence.txt`'s attribution mean anything.

What remains genuinely unmeasured is the absolute number of values each thousand-tick run
draws. Closing it needs a decision the technical owner has not been asked for -- whether a
draw counter belongs on the released surface, or whether a work order may carry a replay of
the whole engine as evidence. `WO-MOK-016` left a comparable clause unwritable and recorded it;
this is the same discipline applied to a narrower gap, and it is raised in
`manual-assessment.md` so that accepting it is an act rather than an omission.

RESULT: PASS on every derivable check -- the correction consumes no entropy, the initialization
replay reproduces all fifteen recorded draw counts and all 120 captured placements at both
commits, every initialization prefix is unchanged, and no `baseline` resolution count moved.
The per-run draw total is recorded as a residual gap in section 5, with its reason.
