# Additivity proof — WO-MOK-005

`WO-MOK-005` states that a test which must change to accommodate this work is a stop condition,
not a task. The check is therefore stronger than a passing count: the engine's test code is
compared byte for byte against the integration branch this work merges into.

## The baseline this work is measured against

$ git log -1 --format='%H %s' origin/master
903c9943d713a3760398026d8c67ee16d4c55deb Merge pull request #9 from mmzen/governance/vrec-mok-004-verified

$ git merge-base --is-ancestor origin/master HEAD && echo "origin/master is an ancestor of HEAD"
origin/master is an ancestor of HEAD

The second check matters. It means every commit on the integration branch is already contained in
this work, so the comparison below is a clean before-and-after of the same lineage and not a
comparison across a fork. An earlier revision of this file compared against 48d16bd4, the commit
this branch was originally cut from. That baseline went stale twice. `master` afterwards merged
`WO-MOK-003`, which added the library target and relocated 15 tests from inline modules into
`tests/` — 5 from `src/cli.rs`, 4 from `src/main.rs`, 6 from `src/simulation.rs` — and then
`WO-MOK-004`, which added 8 help-output cases, taking the engine from 52 tests to 60. Comparing
against 48d16bd4 would have attributed all of that to this work order. This revision compares
against 903c9943.

The count is the weak check. The two below are the ones that could detect a modified test.

## What did change in the engine package

$ git diff --stat origin/master -- src/ tests/ Cargo.toml
 Cargo.toml        |  14 +-
 src/lib.rs        |  29 +-
 src/simulation.rs | 895 ++++++++++++++++++++++++++++++++++++++++++++----------
 3 files changed, 767 insertions(+), 171 deletions(-)

No test body, no test name and no simulation rule was altered. The three files changed in four
ways, and the 171 deleted lines are all of the second, third and fourth kind:

1. Added, in `src/simulation.rs`: the read-only observation surface — `Simulation::snapshot`,
   `advance_tick`, `is_finished`, `termination_reason`, `configuration`,
   `initialization_events` — and the value types they return: `WorldSnapshot`,
   `TerritorySnapshot`, `AgentSnapshot`, `ResourceSnapshot`, `DecisionSnapshot`, `TickOutcome`,
   `Event`, `EventDetail`, `EventType`, `DecisionOutcome`, `RegenerationSkipReason`. Eleven new
   public types, none of which existed at origin/master in any visibility.

2. Widened visibility, in `src/simulation.rs`: exactly five existing types gained `pub`, and their
   fields and members with them.

     at origin/master              in the working tree
     enum Action                   pub enum Action
     enum Direction                pub enum Direction
     enum FoodClass                pub enum FoodClass
     enum Territory                pub enum Territory
     struct Coordinate             pub struct Coordinate

   These are the five `SPEC-MOK-003` names in its narrowing of `SPEC-MOK-002` rule 6, and no
   others. `Policy`, `TerminationReason`, `Config`, `Density`, `RunSummary` and `Simulation` were
   already public at origin/master and were not touched. The ten remaining rule-6 names —
   `Mokiterion`, `Food`, `RelativeDirection`, `ActionResult`, `Observation`, `PerceivedFood`,
   `PerceivedMokiterion`, `SplitMix64`, `DecisionEntropy`, `DecisionSource` — are still private.
   A widened declaration rewrites its own line, so it registers as a deletion plus an insertion.

3. Refactored, behavior-preserving, in `src/simulation.rs`: the places that previously formatted a
   record straight to the writer now build an `Event` value and write that, so the same records are
   available to a caller that is not a writer. `emit_initialization` became
   `initialization_events`, and the run loop's termination record became a value the same way.
   `Simulation::run` and `advance_tick` were routed through one internal step so the two hosts
   share it.

4. Documentation and manifest, in `src/lib.rs` and `Cargo.toml`: the crate doc comment rewritten
   for two hosts, and the workspace table added with the rule-1 amendment cited in a comment. The
   `[dependencies]` table is still empty; see `dependency-review.txt`.

Kind 3 is the only change that could alter observable behavior, and it is exactly what the
unchanged test files pin. `VER-MOK-001` and `VER-MOK-002` assert the text stream's records and
their order literally, including `initialization_is_seeded_and_reproducible` and the per-event
format cases. Those tests are byte-identical to origin/master and pass, which is the evidence that
the refactor preserved the stream rather than an assertion that it did.

The formatter also reflowed parts of `src/simulation.rs`:

$ git diff    --numstat origin/master -- src/simulation.rs   ->  733 insertions, 162 deletions
$ git diff -w --numstat origin/master -- src/simulation.rs   ->  708 insertions, 137 deletions

so 25 insertions and 25 deletions — 50 of the 895 changed lines — are whitespace alone.

## Why the observer package cannot violate this

Every test in `mokiterions-tui` is new: the package did not exist at origin/master, and no
`VER-MOK-001`, `VER-MOK-002` or `VER-MOK-004` case lives in it. Adding a case there changes no
existing test and so is not the situation the stop condition describes. The stop condition is about
a test that must change; the checks above are the ones that could detect it, and they detect
nothing.
