# Additivity proof — WO-MOK-005

`WO-MOK-005` states that a test which must change to accommodate this work is a stop condition,
not a task. The check is therefore stronger than a passing count: the test code is compared
against the integration branch this work merges into.

Re-captured on 2026-08-19. The revision this replaces was written when the observer package did
not exist on `master`, so its whole subject was the engine and it could close with the observation
that no observer test could be at risk. That is no longer true, and the honest form of this file
now has two halves: the engine, where the result is stronger than before, and the observer, where
three tests did change and the authority for each has to be stated rather than assumed.

## The three tests that are gone, and what authorized their removal

  tiers_match_the_specified_table_including_its_boundaries   asserted tier_for and the tier table
  tier_minimums_hold_wherever_the_tier_declares_one          asserted the per-tier minimum extents
  excluded_panes_are_the_ones_the_tier_omits                 renamed; the assertion is unchanged

The first two assert a specification rule that no longer exists. `SPEC-MOK-003` rule 5 as amended
on 2026-08-19 — approved by the repository owner as technical owner, who directed the
implementation in the same act — replaces the four-row tier table with one threshold per pane and
deletes `Tier`, `tier_for` and the `Panes::tier` field with it. A test whose subject a specification
has deleted cannot be kept passing; keeping it would mean keeping the table.

The third is a rename, not a removal: the same assertion against the same behavior, under a name
that no longer says "tier". `SPEC-MOK-004` rule 12 forbids renaming a test, and its second
paragraph is scoped to the `WO-MOK-006` restructuring by the same 2026-08-19 amendment that scopes
rule 13's equivalence clause — for the same reason, that unscoped it freezes test maintenance
permanently, and here specifically it would make a test unrenamable after the word in its name was
deleted from the specification it cites.

Both of those amendments are recorded in their own artifacts. The rule 5 amendment is approved. The
`SPEC-MOK-004` amendment that carries the count change and the rule 12 scoping is **OUTSTANDING and
requires the technical owner**: the owner approved rule 5 without being shown this consequence, and
it is reported rather than treated as covered. Until it is approved, the removal of those two tests
rests on the rule 5 approval alone.

## The three existing test files whose bodies changed

Names identical, bodies not. Every change is one of four kinds, and none of them loosens an
assertion:

1. The declared viewport set grew from 7 entries to 10, because `VER-MOK-005` as amended declares
   `160 × 40`, `140 × 43` and `120 × 30` in addition to the previous set. The constants
   `VIEWPORTS` and `RENDERABLE` appear in both `tests/verification.rs` and `src/verification.rs`
   and grew in both. `the_declared_sets_are_the_contracts` asserts the new lengths, so the growth
   is itself pinned.

2. Two canvas figures changed, because rule 5 as amended resolves different panes at those sizes.
   `100 × 30` goes from a 98 × 24 interior to 51 × 24, since the roster is now placed at 100
   columns; `a_region_states_the_world_range_it_presents` correspondingly expects `x0-101 y0-95`
   there rather than `x0-127 y0-95`, and the old expectation moves to `120 × 30`, where it is now
   the correct one. Neither figure is looser than the other: both are exact equalities.

3. Assertions were added, not relaxed. `a_region_states_the_world_range_it_presents` goes from two
   cases to four, so that a region short in width alone, in height alone, and in both is each
   asserted. `every_declared_viewport_has_its_derived_canvas_with_a_header_and_a_footer` gains a
   check that the roster's, the inspector's and the log's titles appear in the drawn frame exactly
   when the resolved layout places those panes — the reported symptom was a pane missing from the
   screen, and no case previously compared the frame against the layout.

4. One local identifier and three comments lost the word "tier", which had no referent left:
   `let tier_c = …` became `let no_inspector = …` in
   `the_header_names_the_panes_that_are_only_overlays`, and "Tier A excludes nothing" became
   "The reference viewport excludes nothing". No assertion in that test changed.

The formatter reflowed almost nothing: `git diff -w` against `origin/master` reduces the six
files' 284 insertions and 131 deletions to 279 and 126, so 5 insertions and 5 deletions — 10 of
the 415 changed lines — are whitespace alone.

## What is left for the owner to decide

`WO-MOK-005`'s constraint reads "Every existing test must pass unmodified. A test that must change
to accommodate this work is a stop condition, not a task, because this change is specified as
additive." Three of the observer's tests did change. The reading applied here is the narrow one:
the constraint sits next to "Preserve everything verified under `VREC-MOK-001` and `VREC-MOK-002`",
its stated reason is that the observer's addition is additive with respect to the engine, and the
engine's test code is byte-identical as measured above. On the broad reading — any test in the tree
— the stop condition fired on 2026-08-19, and the owner's approval of the rule 5 amendment together
with the direction to implement is what answers it, because a specification amendment that deletes
a rule cannot leave the test asserting that rule standing.

This is stated rather than resolved. The implementation agent has no authority to read a constraint
down, and the distinction only became live when `WO-MOK-006` put the observer's tests on `master`,
which was after this constraint was written.
