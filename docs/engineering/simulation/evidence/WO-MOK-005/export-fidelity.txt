# Export fidelity against the engine binary — WO-MOK-005

`REQ-MOK-025` is a claim about the engine binary's stream, and `verification.rs` compares against
`Simulation::run` called in-process, one function away from the binary's `main`. This file closes
that last step: the real binary is executed as a separate process, its standard output is captured,
and it is compared byte for byte against an export taken from an observed run of the same
configuration.

## Method

An export is the retained records followed by one closing statement, `# retained=N truncated=B`.
The engine binary's stream is the same records followed by its `summary` line. Neither trailer is
part of the other artifact, so each file's last line is dropped and the remainder is compared with
`cmp`, which reports the first differing byte if there is one.

The observer always enables action tracing, because the event log presents traced actions and the
authority overlay maps them; the engine binary makes tracing an option. `--trace-actions` is
therefore passed to the binary so the two streams are the same run rather than two different
configurations. Tracing is observational and changes no outcome, which the engine's own
`action_tracing_is_optional_complete_and_observational` test establishes.

`target/debug/mokiterions.exe`, from a revision of this work that renamed the target; the name

re-derived against the rebuilt `Mokiterions.exe` and is unchanged, which is the expected result
because the engine package — now at `mokiterions-core/`, moved there by `WO-MOK-006` — is
byte-identical to `origin/master` at 05dc6ac in every tracked file, sources, manifest and test
corpus alike; `additivity-proof.txt` shows the two commands. Neither binary's name or path is
changed by this work order. The 20-tick comparison was re-run against the retained files in
`exports/`, so it checks those artifacts and not a fresh pair.
