WO-MOK-010's evidence list asks for "the commit the pre-change capture was taken at, with the
worktree tracked-clean at capture". A statement that a tree was clean is an assurance. What follows
is the same claim measured, and it is stronger: the pre-change capture is reproduced, cell for cell,
from a tree that cannot contain a working-tree modification at all.


1. The pre-change capture is the baseline commit's own output
------------------------------------------------------------

    rm -rf <scratch> && mkdir <scratch>
    git archive 524a6758d74b5240079959e9827ea40a7af22a30 | tar -x -C <scratch>
    cd <scratch> && cargo build --release --offline -p Mokiterions
    bash capture.sh <scratch>/recap

`git archive` writes the commit's trees and nothing else: no untracked file, no working-tree
modification, no index state. Every cell of that capture was then digested and compared with
baseline/pre-manifest.txt on four columns at once — raw SHA-256, byte count, line count and exit code:

    cells in pre-manifest:                                      90
    reproduced exactly (raw digest, bytes, lines, exit):        90
    mismatched:                                                  0

The two cells retained whole and read line by line elsewhere in this packet are among them:

    seed0-baseline-d0.15-traceoff      562c210bd079ffde3e558cce3b107eab5e0ae1ac7f604335d09ea533ca147ab8
    seed42-individual-d0.75-traceon    04008184eeb9533c5ef4ef8e0aa762d8d1c8aecabed5a104b19868e359ae49c4

Any tracked modification present when the pre-change capture was first taken would have to have left
every one of the 90 streams byte-identical to the commit's own output to escape this check.
