  "A reviewer deliberately perturbs the naming step to draw one value from the shared stream,

   not been demonstrated to work."

1. The perturbation
-------------------

Applied to the working tree, and to nothing else. Before:

    name: name_of(number),

After:

    name: {
        // MUTATION CONTROL, VER-MOK-010 acceptance scenario 2. Reverted immediately
        // after measurement; see evidence/WO-MOK-010/analysis/mutation-control.txt.
        let _ = entropy.next_u64();
        name_of(number)
    },

One draw from the shared stream, at the point the name is assigned, and the drawn value discarded.
This is the smallest perturbation that makes naming entropy-consuming while leaving the assigned
name itself correct, so what the oracles catch is the stream position and not a wrong name. No test,
no manifest, no projection and no evidence file was touched for this measurement.

The pre-perturbation file was copied to C:\Users\mathi\simulation.rs.orig, sha256

2. Oracle 2 fails — the recorded stream position
------------------------------------------------

    test result: FAILED. 52 passed; 2 failed; 0 ignored

The two failures are exactly the two instruments oracle 2 rests on, and no others:

    density 0.15% left it before this change

72 is INITIALIZATION_DRAWS for that cell, recorded before this work order; 84 is 72 + 12, one extra
draw per Mokiterion. The inherited instrument and the new one both fail, and they fail with the
arithmetic the perturbation predicts rather than with a vague inequality.

Note which tests did *not* fail, because it is the point of the control: the name tests all passed.
the_names_are_the_specified_twelve, the_reported_record_keeps_the_name_the_agent_holds and the three
public cases in tests/naming.rs are blind to the stream position by construction, and a suite of only
those would have accepted this defect. Oracle 2 is what catches it.

5. Verdict
----------

Oracle 1 fails under the perturbation. Oracle 2 fails under the perturbation, in both of its
instruments, with the predicted arithmetic. The naming step is therefore not merely asserted to be
entropy-neutral: the checks that assert it have been shown to reject a naming step that is not.

RESULT: PASS — the acceptance scenario is satisfied.
