The observer's diff: one line, and it is a parameter's name
----------------------------------------------------------

    57c57
    < spatial.rs       item  pub fn agent_glyph(id: &str) -> char {
    ---
    > spatial.rs       item  pub fn agent_glyph(name: &str) -> char {

The parameter is renamed because what it receives is now a name rather than an identifier. Its
type is `&str` before and after and the return is `char` before and after, so the item's shape is
unchanged and no caller outside the crate is affected. This is the only difference in 125 lines.
SPEC-MOK-004 rule 6's 2026-08-19 amendment for this work order records the interface as unchanged;
this is the measurement behind that sentence.

`Observer::name_of` does not appear in either enumeration, because it is `pub(crate)` and
interface.py excludes restricted visibility, as rule 6 does. That is the decision that keeps the
figure at 94: the observer's presentation reads names through a crate-internal accessor, and a test
that wanted it would be an internal-tier test rather than a reason to widen it.


Reconciliation with SPEC-MOK-004 rule 6's recorded 94 / 118 / 24

declarations, which are the module tree rather than members of the interface. Removing those seven
lines from the mechanical figure gives the recorded one exactly:

`main.rs` and `verification.rs` contribute nothing: the binary declares no public item, and
`verification.rs` is one `#[cfg(test)]` module, which rule 7 keeps out of the library target and
which interface.py skips whole by brace balance. That skip is also what keeps the four test hooks —
including `replace_snapshot_for_test`, which this work order's ninth internal test uses — out of the
interface.


The engine: identical at both revisions
---------------------------------------

    diff core-pre.txt core-post.txt
    (no output)                        ENGINE INTERFACE IDENTICAL

No item entered or left the engine's public interface, and no item's rendered declaration changed
by one character. That is what has to be true for SPEC-MOK-002 rule 5 to need no amendment under
this work order, and it is why the naming chain amends SPEC-MOK-001, SPEC-MOK-003 and SPEC-MOK-004
but not SPEC-MOK-002.

Rule 5 lists the engine's items by hand with a justification each and records no total, so the
figure above is not a comparison against a recorded number; it is a comparison of the engine
against itself. The name reaches the observer without touching that interface because it travels in
`EventDetail::AgentInitialized`, whose rendering rule 5 does not enumerate field by field:
`Mokiterion.name` is a private field of a private struct, and `AgentSnapshot` deliberately does not
carry a name, exactly as it deliberately does not carry `waste_tolerance`.
